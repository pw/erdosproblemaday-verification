## Verdict

Let `a(n)` be the minimum size of a maximal Sidon subset of `{1,...,n}`.
Together with the previously frozen certificate through 95, this bundle proves

```text
a(66) = a(67) = 6,
a(n) = 7 for every 68 <= n <= 101,
a(102) = 8.
```

This extends the finite table associated with Erdos Problem 156. It does not
resolve the parent asymptotic question about `O(n^(1/3))` maximal Sidon sets.

## Blocking reduction

For a Sidon set `A`, adjoining an integer `x` fails exactly when a new sum
`x+a` or `2x` equals an old unordered pair sum. Equivalently, using positive
differences `D(A)`, the blocked integers are

```text
A union {a-d, a+d : a in A, d in D(A)}
  union {(a+b)/2 : a<b in A and a+b is even}.
```

If a maximal set in `{1,...,n}` is translated so its minimum is zero, it is a
normalized ruler `R={0=r_1<...<r_k=L}` with `L<=n-1`. Its translated domain
is an `n`-integer interval containing `[0,L]`, and every integer of that
interval is blocked. Conversely, any blocked `n`-integer interval containing
the ruler translates to a maximal set in `{1,...,n}`. Thus it is enough to
enumerate normalized Sidon rulers and measure the consecutive blocked
component containing their hull.

## Sizes at most six

Three exact programs enumerate every normalized set of size at most six and
maximum mark at most 101. The first maintains positive differences, the
second maintains unordered pair sums, and the third enumerates unpruned
combinations and tests insertions directly. The two optimized engines agree
on the following complete counts:

| size | raw sets | Sidon sets | hull covered | longest blocked run |
|---:|---:|---:|---:|---:|
| 1 | 1 | 1 | 1 | 1 |
| 2 | 101 | 101 | 2 | 4 |
| 3 | 5,050 | 5,000 | 8 | 10 |
| 4 | 166,650 | 156,816 | 76 | 22 |
| 5 | 4,082,925 | 3,316,012 | 1,102 | 42 |
| 6 | 79,208,745 | 46,198,688 | 20,166 | 67 |

The first size-six maximum encountered is `{0,7,19,22,28,39}`, whose blocked
component is `[-15,51]`. In particular, no set of size at most six is maximal
on any interval of length at least 68 in the range needed here.

The two optimized programs prune only after an already repeated difference or
pair sum; later marks cannot repair such a collision. The direct program has
no prefix pruning. The maintained base-difference masks use coordinates at
most 101, safely below the 128-bit mask width. The direct audit's larger
insertion bitset covers coordinates through 304, and all blocked arrays
include the whole possible range `[-L,2L]` plus unblocked sentinels.

## Seven marks

`verify_size7_parallel.cpp` enumerates every normalized seven-mark Sidon ruler
with maximum mark at most 101. It creates 4,656 disjoint tasks indexed by the
maximum and first positive mark. Within a task it chooses the remaining marks
in increasing order, pruning only repeated positive differences. Every task
is processed exactly once by the OpenMP loop; all counters are thread-local
until atomic accumulation, and all best-record updates hold a mutex.

The complete run reports:

```text
endpoint attempts:       659,485,834
seven-mark Sidon rulers: 386,623,922
hull-covered rulers:         455,390
longest blocked run:             101
ruler:              {0,24,27,35,39,41,75}
blocked component:             [-17,83]
```

Any seven-element subset of `{1,...,102}` has normalized maximum at most 101.
Since the exhaustive longest blocked run has length 101, none can be maximal
in a 102-integer domain. Combined with the smaller-size enumeration, this
proves `a(102)>=8`.
