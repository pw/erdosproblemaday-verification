All live checks below were performed on 2026-08-11 UTC.

## Problem record

`https://www.erdosproblems.com/1106` was fetched through a browser and frozen
as `live_1106_20260811.txt`. At fetch time it said:

* status OPEN;
* zero comments and zero claimed proofs;
* no listed current workers or interested collaborators;
* last edited 2025-11-16; and
* the known bounds are asymptotic (`F(n) -> infinity` and
  `F(n) >> log n`), while the eventual inequality remains a question.

## Published finite data

The rendered OEIS records are frozen as `oeis_A194259_20260811.txt` and
`oeis_A194261_20260811.txt`.

* A194259 defines `F(n)`, labels `F(n) > n` for `n > 115` as an appearance,
  and links a table only for `1 <= n <= 10000`.
* A194261 defines the smallest new prime divisor of `p(n)` (or 1) and links a
  table only for `1 <= n <= 10000`.

The corresponding table files were fetched directly from:

* `https://oeis.org/A194259/b194259.txt`
* `https://oeis.org/A194261/b194261.txt`

Both frozen files contain exactly 10,000 contiguous rows. Their hashes are in
`SHA256SUMS` and are hard-coded in the verifier.

## Historical primary sources

The `sources/` directory freezes the following records and full texts:

* A. Schinzel and E. Wirsing, *Multiplicative properties of the partition
  function*, Proc. Indian Acad. Sci. Math. Sci. 97 (1987), 297-303. Official
  academy record and PDF:
  `https://www.ias.ac.in/describe/article/pmsc/097/01-03/0297-0303` and
  `https://www.ias.ac.in/article/fulltext/pmsc/097/01-03/0297-0303`.
* J. Cilleruelo and F. Luca, *On the largest prime factor of the partition
  function of n*, Acta Arith. 156 (2012), 29-38, DOI
  `10.4064/aa156-1-4`. The introduction restates the Schinzel-Wirsing bound
  as `F(N) >= (1-epsilon) log(N)/log(2)` for sufficiently large `N`.
* K. Ono, *Distribution of the partition function modulo m*, Ann. Math. 151
  (2000), 293-307, arXiv `math/0008140`. Its divisibility theorem supplies
  historical context but is not used by this finite certificate.

PARI's official arithmetic-function manual states that `factor` may return
large pseudoprimes and directs users to `isprime` to prove primality:
`https://pari.math.u-bordeaux.fr/dochtml/ref/Arithmetic_functions.html`.
The verifier follows that distinction explicitly.

## Discovery data

`extension_partitions_10001_10100.txt` was generated by the same exact
pentagonal recurrence used in the verifier. The values were submitted to the
public FactorDB API to locate candidate factors; raw responses are frozen in
`factordb_extension_10001_10100.jsonl`. One suitable candidate per index was
written to `extension_witnesses_10001_10100.tsv`.

FactorDB's status labels and primality labels are not proof inputs. During
verification, all partition values are recomputed, every division is exact,
all witnesses are checked for distinctness, and all witness primalities are
proved again with PARI `isprime`.
