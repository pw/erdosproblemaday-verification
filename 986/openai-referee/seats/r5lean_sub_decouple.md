## Running notes (appended incrementally)

### N1. Band/class parameters (ReciprocalBands, ReciprocalStageArithmetic, ForwardPreparedStage)
- Lean `BandCondition σ K u i` (Marking/ReciprocalBands.lean:15-17): i even -> integer band |u-(i/2+1)σ|≤K (r=1..4); i odd -> open band (i/2+1)σ+K<u<(i/2+2)σ-K (upper rank 2..4). Matches paper's 4 integer + 3 open bands (tex ~l.199-206).
- **Parameter shift**: Lean instantiates band width = D·σ^{3β} (Iteration/ForwardPreparedStage.lean:30,66 `DomainClass (D*σ^(3*beta η))`, `BandCondition σ (D*σ^(3*beta η))`), i.e. the paper's K, NOT the paper's K_*=Dσ^{6β}. Goodness cutoff s = D·σ^{2β} (Marking/ReciprocalStageArithmetic.lean:39-41: `log32+3*(Dσ^{2β})<Dσ^{3β}`, `log32+Dσ^{3β}+3(Dσ^{2β})<σ`), vs paper's K=Dσ^{3β}. The whole ladder is shifted down by σ^β; ratios preserved (s=o(width), width=o(σ)), so logic same. Dσ^{6β} survives only in the code-domain slack (ReciprocalStageArithmetic.lean:20-22). Harmless re-parameterization but a literal mismatch with eq:stage-parameters / band definitions.

### N2. Class decomposition + pigeonhole (task item 1)
- `SlotClass := Fin 7 ⊕ (Fin 7 ⊕ (Fin 5 × Fin 5))`, 39 classes (Marking/MarkingClasses.lean:11-13): 7 forward-oriented reciprocal bands, 7 reverse-oriented, 25 (r,s) high labels.
- `classValid` (MarkingClasses.lean:24-31): reciprocal = ∃u∈[σ,4σ], ForwardCaps/ReverseCaps (first-endpoint image ≤32e^{5σ-u}, second ≤32e^u, Marking/MarkingClassDomains.lean:58-64) ∧ BandCondition; high = popular in both scans with r+s>5. `marking_domain_dichotomy` (MarkingClassDomains.lean:167-191): poor in forward ⇒ ForwardCaps; poor in reverse ⇒ ReverseCaps; popular both and r+s≤5 ⇒ ForwardCaps with u=rσ (`popular_reciprocal_caps`, ReciprocalBands.lean:49-68). SAME as paper (eq:reciprocal-caps / eq:high-caps reduction). Paper's u=max(σ,min(4σ,log|Z_l|)) is replaced by an existential u — fine (weaker requirement, only used through caps).
- Minor: paper says "whenever a rank is four orient so r=4"; Lean keeps all 25 (r,s) labels (no orientation normalisation at this stage) — harmless.
- Pigeonhole: `marking_fixed_class` (Marking/TwoScanContext.lean:142-158): if 39·l + expensiveBound ≤ N then ∃ class a with P(selectedClassEvent l ... a) ≥ 1/39 (pointwise ≥39l unspecified positions ⇒ some class has ≥l). `classStream` (MarkedStreamExtraction.lean:35-41) = restrict to that event then `extract` the first l class positions; density ≤ 39·density (`classStream_density`, :68-79). SAME as paper ("event of probability bounded below ... retain first ⌊ck⌋ positions"), constant c = 1/39 per-position fraction.
- Stage lengths (Marking/CompressionStage.lean:50-60 + Iteration/StageCuts.lean:9-24): class retained length m = n/100 (needs 39m+expensive≤n, expensive ≤ 9600 qσ); final output length n/20000 = (n/100)/200, required ≤ m/100 (ForwardPreparedStage.lean:28 `(l:ℝ)≤ m/100`). So StageCuts' n/100 = "fixed class with ≥ck positions" (c=1/100), n/20000 = surviving output tuple length after windows/targets (fixed fraction 1/20000 per stage). `eventually_marking_small` (StageCuts.lean:26-43) only gives n≥40000 and 19200qσ ≤ n (so expensive positions fit). Consistent with paper's Θ(k).
- D definition matches paper: `D=σ^beta η*(1+Λ/k₀+Δ*σ^(-η))` (CompressionStage.lean:35).
